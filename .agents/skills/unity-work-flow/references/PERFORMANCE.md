# iOS 性能与稳定性

性能结论必须带上下文：设备型号与芯片档位、iOS 版本、构建类型、画质/分辨率、场景、玩家状态、网络、测试时长、温度起点和采样工具。Development Build 的绝对数值不能直接作为发布构建结论。

根据产品目标设阈值，至少考虑：

- FPS、帧时间分位数和长帧；区分 CPU main/render、GPU 与等待。
- managed/native/GPU 内存、峰值、场景切换后回落和内存警告处理。
- 冷/热启动、首帧可交互时间、场景加载与 Addressables 下载。
- 安装/下载大小、按需资源与重复依赖。
- 15–30 分钟后的热状态、降频、耗电和网络流量。
- 崩溃、ANR 类卡死、OOM、后台恢复和多次场景循环稳定性。

先用 Profiler、Memory Profiler、Instruments、MetricKit/Organizer 或包体报告定位瓶颈，再优化。不要以禁用功能、降低画质或扩大对象池作为无证据默认方案。对象池要验证峰值、回收和跨场景生命周期；资源卸载要避免仍被引用或下一帧抖动重载。
